# safe-bundle

Local-first redaction and safe support bundle CLI for developer diagnostics.
It helps developers share logs, configs, and support archives without
accidentally publishing secrets, local identity, private network details, or
auth material.

## Project Stage

**Stable 1.x OSS crate.** `1.0.0` established the stable local safety contract:
installable CLI, repository policy, documented bundle schema, CI/automation
support, and release integrity checks. `1.1.0` shipped the distribution and
policy-UX layer: crates.io, GitHub Release archives, Homebrew, Scoop, shell
completions, config helpers, release verification, and package-manager recipe
generation. Post-release `main` is on the next development version
(`1.1.1-alpha.0`).

## Architecture

Single Rust CLI crate. `src/main.rs` enters the clap command surface defined in
`src/cli.rs`; reusable logic lives in `src/lib.rs` modules:

- `detectors.rs` defines built-in detector catalog and provider token shapes.
- `engine.rs` applies profiles, allowlists, placeholders, and redaction events.
- `formats.rs` validates JSON, JSONL, TOML, YAML, and env-like outputs after
  redaction.
- `config.rs` loads `.safe-bundle.toml` repository policy, custom detectors,
  allowlists, and path profile overrides.
- `input.rs` walks selected files, skips binary/non-UTF-8/oversized inputs, and
  sanitizes archive paths.
- `archive.rs` writes and verifies schema-v1 `.safe-bundle.zip` bundles.
- `report.rs` emits summaries, public events, receipts, and SARIF.
- `model.rs` holds shared data contracts.

The CLI is local-only: no telemetry, hosted service, or network call during
normal scrub/bundle/inspect operation. Network is used only by maintainer
release helper scripts that intentionally download or verify published release
assets.

## Command Surface

- `scrub` redacts stdin or selected files.
- `bundle` creates redacted `.safe-bundle.zip` support archives.
- `inspect` summarizes and verifies generated bundles.
- `rules list` exposes the detector catalog.
- `rules test --format <text|json|markdown>` reports fixture redaction
  summaries.
- `config init`, `config validate`, and `config inspect` manage repository
  policy.
- `completions <shell>` generates Bash, Elvish, Fish, PowerShell, and Zsh
  completion scripts.

## Market Space

- **Category:** Developer privacy / support artifact redaction CLI
- **Adjacent tools:** Gitleaks, TruffleHog, detect-secrets, git-secrets,
  secretlint, scrubadub, ad hoc support-bundle scripts
- **Positioning:** Not a repository leak scanner and not a DLP platform.
  `safe-bundle` is the local pre-share step before opening public issues,
  handing diagnostics to support, or pasting logs/config into an LLM. It
  preserves diagnostic shape while removing common credentials, identity, and
  private network details.

## Competitive Leads

- Local-first by default: no account, service, telemetry, or cloud dependency.
- Support-bundle workflow, not just raw text scanning: redacted files, manifest,
  skipped-file records, public redaction events, checksums, and README.
- `inspect --verify` validates schema, checksums, event parseability, redaction
  counts, and logical bundle hash.
- Public metadata never includes raw matched values; private receipts use hashes
  and source spans for sender-side correlation.
- Structured format preservation for JSON, JSONL, TOML, YAML, and env-like
  inputs.
- Repository-local policy via `.safe-bundle.toml`, including allowlists, custom
  detectors, and path profile overrides.
- Provider detector coverage for common developer tokens across cloud, SaaS,
  messaging, API, and payment providers.
- Release discipline: cross-platform CI, MSRV gate, dependency policy, package
  and publish dry-run, GitHub artifact attestations, checksum sidecars, release
  verifier, Homebrew/Scoop recipe generation.

## Key Gaps

- False negatives remain the primary residual risk; new token formats need
  detector fixtures before claims expand.
- Binary, image, screenshot, and arbitrary proprietary prose redaction are out
  of scope.
- Legal anonymization and compliance-grade de-identification are explicit
  non-goals.
- Homebrew/Scoop metadata is published, but local package-manager install smoke
  cannot run on the current Windows release machine unless those package
  managers are installed.
- Winget packaging is deferred until the Windows distribution format is final.

## Design Priorities

- **Local-first safety:** process files locally and keep original inputs in
  place.
- **No public raw secret leaks:** summaries, events, manifests, skipped records,
  and SARIF must avoid raw matched values.
- **Stable diagnostic shape:** deterministic placeholders should preserve enough
  context for debugging.
- **Human review remains mandatory:** redaction reduces sharing risk but does
  not certify an artifact as safe to publish.
- **Schema stability:** `.safe-bundle.zip` schema-v1 compatibility matters after
  1.0.
- **Fixture-backed detector work:** every detector expansion needs positive and
  false-positive coverage where plausible.
- **Release integrity:** final crates.io publish must come from the release tag,
  not post-release `main`.

## Release Notes

```powershell
# Publish from the exact release tag, never from post-release main.
git switch --detach vX.Y.Z
cargo publish --dry-run --locked
cargo publish --locked
git switch main
```

GitHub Release assets are generated by the `Release` workflow from annotated
`vX.Y.Z` tags. Verify assets with:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-release.ps1 -Tag vX.Y.Z
```

Package-manager recipes are generated after the GitHub Release is live:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\generate-packaging-recipes.ps1 -Tag vX.Y.Z
```
